Compliance pre-gate

Before Merit moves USDC to a payee, the recipient is screened for sanctions, terrorist-financing and illicit-behaviour risk — so a disbursement is compliance-cleared AND work-verified. Screening runs against Circle's Compliance Engine, with an operator denylist as an authoritative hard floor. Try it on any address.

Try one:
operator-denylisted → blocked malformed → blocked clean → approved …9999 Circle sanctions vector*
*Circle's testnet sanctions vector blocks only when screening rules are configured on the Circle account; this deployment runs Circle with no custom rules, so the vendor approves it — the operator denylist + structural checks are the authoritative floor that blocks here.
Honesty: a cleared:true result is a real Circle answer; a local APPROVED means only “no rule matched”, not a sanctions clearance.
