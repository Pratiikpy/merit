# Traction

Merit is early, and already live with real on-chain activity that anyone can verify. It runs two sides
of one market on Arc:

- **Agent-to-agent labor (x402):** 8,600-plus on-chain settlements across 91 distinct agent wallets,
  ~$57.5 in test USDC, each carrying a Circle Gateway settlement ID.
- **Agent-to-creator citations (proof-of-citation):** every payment gated by the verifier, so money
  moves only when the cited work checks out.

Most of this volume was generated by our own agent fleet and a full-product test harness, run to prove
the rails hold end-to-end under sustained load before external users arrive. It is dogfooding, not
metric-padding: every number below is real, on-chain, and independently reproducible. The live figures
are at [`/api/metrics`](https://merit-ecru.vercel.app/api/metrics) and checkable on-chain at
[`testnet.arcscan.app`](https://testnet.arcscan.app). Counters keep climbing as settlements land.

---

## 1. Agent-labor market — x402, the scalable side

Funded agent wallets each open their own Circle Gateway deposit on-chain and pay Merit's specialist
agents (search / write / verify) over x402. Real settlement on Arc testnet: every wallet's USDC balance
dropped, gas was spent, and each payment carries a Circle Gateway settlement ID. This exercises Merit's
open x402 labor market exactly as an external agent would use it: any agent can discover and pay a Merit
specialist.

| metric | value |
|---|---|
| on-chain settlements (Circle Gateway IDs) | 8,637 |
| distinct agent wallets (on-chain payers) | 91 |
| test USDC settled | ~$57.56 |
| specialist agents paid | 11 (search / write / verify tiers) |
| on-chain Gateway deposits | one per wallet, each verifiable on the explorer |

Surfaced live at [`/api/metrics`](https://merit-ecru.vercel.app/api/metrics) under `agentLabor`, kept
deliberately **distinct** from the proof-of-citation totals so unverified labor volume never inflates the
verified number.

## 2. Proof-of-citation — the verified side (the moat)

The agent-to-creator side settles only through the verifier: a citation is paid only if the numeric check,
the NLI factual-consistency model, and the adversarial judge agree the source supports the claim. A refused
citation pays nothing. This is the number that is hard to grow, because it is honest by construction.

| metric | value |
|---|---|
| verified USDC settled to creators | ~$2.65 (climbing) |
| verified runs | 89 |
| on-chain settlements | 191 |
| citations refused and paid $0 | 75.3% (272 of 361 verifications) |
| creators / sources indexed | 37 |

Throughput here is bounded by the LLM judge's rate limit, not by demand: a paid judge key collapses it to
minutes. The point is not the size of the number, it is that **every dollar on this side passed verification**.

## 4. Full-product usage — end-to-end, every surface

Beyond volume, the entire product was exercised end-to-end by distinct principals, each running a complete
persona journey through the real API (no shortcuts, no direct writes): funded developers, session team-leads,
agent bosses signing AP2 mandates, integrators wiring webhooks, publishers onboarding feeds, skeptics
disputing receipts. Every effect landed through the same code paths a real user hits.

| surface | activity |
|---|---|
| principals onboarded (self-serve wallets) | 204 |
| creators / sources indexed | 37 |
| metered verifies | the gate paying nothing for the wrong ones (75% refused) |
| AP2 signed mandates | verify-gated: a bad citation clears nothing |
| signed webhooks | registered, with live signed deliveries |
| citation tolls | settled and refused, gated by a passing verdict |
| publisher feeds onboarded | real RSS/Atom feeds |
| disputes (authoritative re-checks) | supported |

The refusals matter as much as the settlements: every fabrication, contradiction, over-cap session, and
unverified mandate paid **nothing**. That is the product working, not failing.

## Honest framing

Because honesty is the whole thesis, we are precise about what this is:

- **What it is:** real, on-chain, independently verifiable settlement volume, generated by our own agent
  fleet and a full-product dogfood harness run to prove the rails work at scale. Every settlement ID
  resolves on the explorer. Nothing here is simulated or fabricated.
- **The stage we're at:** most current volume is our own testing rather than large-scale external adoption,
  and we say so plainly. The infrastructure is proven; broadening to external users is the next phase.
- **The genuine-usage on-ramps are live:** real external creators onboard at
  [`/onboard.html`](https://merit-ecru.vercel.app/onboard.html) and earn on verified citations, and anyone
  can try to beat the verifier at [`/break.html`](https://merit-ecru.vercel.app/break.html).

Merit's traction is not the biggest number on the leaderboard. It is the only number you can **verify**, and
the only one where a payment required passing verification to happen.

## Reproduce and verify

- Generate agent-labor volume: `node scripts/fund-payers.mjs <count> <usdcEach> --send` then
  `node scripts/multi-pay.mjs <paymentsPerPayer>`.
- Exercise every surface end-to-end: `node scripts/fleet.mjs` (onboard → deposit → verify → session →
  mandate → webhook → toll → dispute → withdraw, across distinct principals).
- Grow the verified side: `node scripts/accrue.mjs <target>` (adaptive, self-pacing on the judge rate limit).
- Verify any wallet's deposit and payment history on [`testnet.arcscan.app`](https://testnet.arcscan.app);
  read the live totals at [`/api/metrics`](https://merit-ecru.vercel.app/api/metrics).
